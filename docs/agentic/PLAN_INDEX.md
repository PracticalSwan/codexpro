## Execution rule
Plans 12-21 were explicitly authorized as one cumulative batch and executed on the dedicated `roadmap/plans-12-21` worktree/branch. Plans 12-17 and 20 are verified; Plan 18 Stage 1 is verified while interactive approvals remain capability-gated; Plan 19 is blocked by the current MCP/ChatGPT Tasks capability gate; Plan 21 Stage A is live-verified on Windows while Linux-host validation remains pending and Goals stay host-only. The cumulative build/smoke/stress/audit/release-pack/diff gate passed on 2026-09-07. Each subsystem retains its independent acceptance criteria and status above.

A running CodexPro runtime must remain untouched unless the user separately approves stopping it for a required operation. Agents may never start or restart CodexPro; after an approved stop it must remain stopped. The unified plan defines how to defer global reinstall when this runtime boundary prevents it.

Plans 22–28 are planning-only and are controlled by [the deadline-resilience execution plan](../superpowers/plans/2026-09-08-deadline-resilience-execution.md). Tool-time awareness is planned on by default: normal bounded mode defaults to 1,200,000 ms (20 minutes), finite values are 5–60 minutes, and explicit Unlimited/observe is available only for harmless host-window discovery. Every effective value is explicitly a transport boundary: implementation must preserve full task scope, acceptance criteria, review depth, and required verification by yielding to resumable processes/jobs/Goals/batches instead of rushing.

Plans 29–37 are planning-only and controlled by [the task-aware browser-continuation execution plan](../superpowers/plans/2026-09-08-task-aware-browser-continuation-execution.md). Continuation is optional/default-off and independent of tool-time awareness. Version 1 is human-gated: a dedicated signed-in browser profile and optional paired private Telegram bot may notify/prepare the bound chat, but every continuation dispatch requires a current explicit browser or Telegram user action. Implementation must STOP for browser authentication and for Telegram BotFather/token/pairing user steps, resuming only after the user completes them and sends `continue`.
Manual user prompts outrank prepared continuation: stale browser/Telegram actions are invalidated, then the host model reconciles the current prompt as resume, redirect, supersede-new-task, or cancel. For this user's future authorized local setup, continuation and Telegram are explicitly enabled in their profile while package defaults remain off.
